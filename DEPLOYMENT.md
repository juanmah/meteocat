# meteocat — Deployment

This document describes the two deployment modes of the project.

---

## Use Case 1 — Git clone, run locally

The user clones the repo and runs commands directly from the project directory.

```
~/projects/meteocat/   ← git clone target, also the working directory
```

### How it works

1. `uv sync` creates `.venv/` inside the project root.
2. The `meteocat` console script entry point (`meteocat.cli:app`) is available via `uv run meteocat`.
3. All output paths in `meteocat/config.py` are relative to the working directory:
   - `background/background_raw.png`
   - `background/background_4K.png`
   - `background/background_4K_dark.png`
   - `radar.png`
   - `wallpaper/wallpaper.png`
   - `wallpaper/wallpaper_dark.png`
4. The systemd service files are generated by `meteocat install-systemd` with `WorkingDirectory` set to the project root.

### Running commands

```bash
uv run meteocat check-dependencies
uv run meteocat generate-background
uv run meteocat generate-wallpaper
```

### Key implication for development

All file paths are relative to `cwd`. If the working directory changes, the paths in `WallpaperSettings` must be updated accordingly. The `generate-wallpaper` command will fail if `background_4K.png` does not exist relative to cwd.

## Use Case 2 — Arch Linux AUR install

The user installs the package from the AUR. After install:

- `/usr/bin/meteocat` exists (entry point from `pyproject.toml` `[project.scripts]`).
- A systemd **user** service points to a working directory in the user's home (e.g., `~/.local/share/meteocat/` or the AUR build directory).

### How it works

1. The AUR PKGBUILD patches `config.py` before building so `service_exec` defaults to `/usr/bin/meteocat`. The user runs `meteocat install-systemd`, which writes the systemd unit files to `~/.config/systemd/user/` with `WorkingDirectory` set to the `working_directory` setting (default: `~/.local/share/meteocat`).
2. All generated files (background images, radar.png, wallpapers) are written relative to that `WorkingDirectory`.

### Systemd file management

The `service_exec` field in `WallpaperSettings` controls the `ExecStart` line. Default is `/usr/bin/uv run meteocat` (Use Case 1). For AUR installs (Use Case 2), the PKGBUILD patches this to `/usr/bin/meteocat` before building so the service uses the installed binary directly without `uv`.

### Key implication for development

The AUR package must ensure the working directory exists and contains (or can contain) the `background/` and `wallpaper/` subdirectories. The `background_4K.png` file is a prerequisite for `generate-wallpaper`; if missing, the command auto-generates it via `generate-background`, but this requires network access to meteo.cat tile servers.

## Project structure reference

```
meteocat/
├── pyproject.toml              # package config, entry point meteocat = meteocat.cli:app
├── Makefile                    # install-service, generate-wallpaper, etc.
├── meteocat/
│   ├── cli.py                  # typer CLI: check-dependencies, generate-background, generate-wallpaper
│   ├── config.py               # WallpaperSettings pydantic model (all paths + tile params)
│   └── systemd.py              # embedded service/timer templates, install/uninstall logic
├── background/                 # output: raw, 4K, 4K_dark images
├── wallpaper/                  # output: final wallpaper.png / wallpaper_dark.png
└── stuff/                      # auxiliary assets
```
